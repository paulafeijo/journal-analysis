# Data Fetching – Fetch Competitor Authors

## fetch_competitor_authors.py

Step 6 of `main_script.py`.

## Location

`data_fetching/fetch_competitor_authors.py`

## Overview
Fetches detailed author and affiliation information for **each competitor journal's articles** by querying the OpenAlex API (using the DOI of each article).
It processes all articles in parallel to speed up retrieval, and stores, per competitor ISSN:
- `authors.json` → list of authors with metadata per article
- `failed_dois.txt` → list of DOIs that could not be retrieved after retries

## Inputs

### Required
- **Base ISSN** (string) — provided via **STDIN** from ``main_script.py`.
- **Competitor list** – `data_fetching/data/<BASE_ISSN>/top_competitors.json` (output of `top_competitors_citations.py`). Used to enumerate competitor ISSNs.
- **Articles file** – must already exist at: `data_fetching/data/<COMPETITOR_ISSN>/articles.json` (generated by `fetch_competitor_articles.py`). If missing, that ISSN is skipped with a warning.


## Outputs

### Files
- **Authors (JSON Lines)**: `data_fetching/data/<COMPETITOR_ISSN>/authors.json`
 Each record includes:
 - `doi` — article DOI
 - `published_date` — publication date from article dataset
 - `issn` — ISSN(s) for the article
 - `oa_status` — Open Access status from OpenAlex (open, closed, etc.)
 - `type` — work type (e.g., journal-article)
 - `author_name` — author’s display name
 - `author_position` — position in author list (first, middle, last)
 - `orcid` — ORCID ID (if available)
 - `affiliation` — first listed institution name
 - `country` — country code of the institution
 - `author_id` — OpenAlex author ID
- **Failed DOIs (TXT)**:
 - `data_fetching/data/<COMPETITOR_ISSN>/failed_dois.txt`

### Console output
For each competitor:
- Start message confirming the ISSN is being processed: `"[i/N] 🔍 Fetching author information for ISSN <ISSN>..."`
- Progress bar via `tqdm` showing progress.
- Summary lines:
  - `📊 Fetched authors for <count> articles``
  - `❌ Failed DOIs: <count>`
- Save confirmations indicating where `authors.json`and `failed_dois.json` were saved. 

## Usage

### Parameters and configuration
- API endpoint: `https://api.openalex.org/works/doi:<DOI>`
- Headers: `{"User-Agent": "mailto:paulafmed@gmail.com"}` (replace with your email if needed)
- Concurrency: `MAX_WORKERS = 10` (threads processing DOIs in parallel)
- Retries: `RETRIES = 3` attempts per DOI
- Retry delay: `RETRY_DELAY = 2` seconds between attempts
- Runs one HTTP request per DOI; parallelism speeds things up but be mindful of API courtesy.

### Error Handling
- Non‑200 or network errors: retried up to `RETRIES`; after exhausting retries, the DOI is counted as failed. Function returns an empty list on failure.
- Missing articles file for a competitor ISSN: prints a warning and skips that ISSN.
- After each ISSN: writes `failed_dois.json` listing any DOIs without author data.

### Data shaping
For each DOI (article), the script expands authorships from OpenAlex into a row per author with the following fields:
- `doi` — the article DOI (string)
- `published_date` — propagated from `articles.json` (string; may be `YYYY`, `YYYY-MM`, `YYYY-MM-DD`, or `null`)
- `issn` — comma-separated ISSN(s) from the article record (string)
- `oa_status` — Open Access status from OpenAlex (open, closed, unknown, etc.)
- `type` — Crossref/OpenAlex work type (e.g., journal-article)
- `author_name` — author’s display name
- `author_position` — first, middle, or last (from OpenAlex authorships)
- `orcid` — ORCID if available
- `affiliation` — first listed institution’s `display_name` (or `null` if none)
- `country` — first listed institution’s `country_code` (or `null`)
- `author_id` — OpenAlex author ID

**Shaping choices**
- Only the first institution per authorship is captured (keeps schema simple).
- Missing fields are set to `null` (JSON) to preserve a consistent schema.
- Output format is JSON Lines to support large, streamable datasets.

### Dependencies
- Python packages: `requests`, `pandas`, `tqdm`
- Standard library: `os`, `sys`, `time`, `logging`, `concurrent.futures`
